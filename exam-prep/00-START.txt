LINUX: ОТ ЧИСТОЙ VM ДО API (Ubuntu 22.04/24.04)
Команды выполняй по одной, только после успеха предыдущей. # — комментарий.
Ubuntu: обычный пользователь с sudo, не root. Пароль sudo/SSH не виден при вводе.

0. VIRTUALBOX — ДО ЗАПУСКА UBUNTU
Выключи VM → Настроить → Сеть → Адаптер 1 → NAT → Дополнительно →
Проброс портов. Добавь два правила (IP гостя оставь пустым):
  ssh: TCP | IP хоста 127.0.0.1 | порт хоста 2222 | порт гостя 22
  api: TCP | IP хоста 127.0.0.1 | порт хоста 8080 | порт гостя 80
Нажми OK в пробросе, затем OK в настройках VM: сохрани ОБА окна. Запусти VM.

1. УСТАНОВКА — Ubuntu Bash (терминал внутри VM)
sudo apt update # Обновить список доступных пакетов.
sudo apt install -y git curl nginx openssh-server dotnet-sdk-8.0 # Установить всё для SSH, сборки и HTTP.
dotnet --version # Проверить SDK: ожидается 8.0.x; пакет не найден → HELP §4.

2. SSH — Ubuntu Bash (пока в консоли VirtualBox)
sudo /usr/sbin/sshd -t # Проверить конфигурацию SSH; успех — нет вывода.
Если no hostkeys available / отсутствуют host keys:
sudo ssh-keygen -A # Создать ТОЛЬКО отсутствующие ключи сервера; существующие сохраняются.
Если Missing privilege separation directory: /run/sshd:
sudo install -d -m 755 -o root -g root /run/sshd # Создать служебный каталог SSH до запуска.
После исправления повтори проверку; при другой ошибке → HELP §12.
sudo /usr/sbin/sshd -t # Убедиться, что ошибок больше нет; иначе остановись.
Только если служба прежде была failed:
sudo systemctl reset-failed ssh # Сбросить прежний сбой и ограничение повторных запусков.
sudo systemctl enable --now ssh # Включить автозапуск и запустить SSH.
sudo systemctl status ssh --no-pager -l # Проверить active (running); иначе HELP §12.
whoami # Узнать логин Ubuntu для подключения из Windows; не root.
sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub # Показать ED25519 fingerprint своей VM для сверки.

Windows PowerShell (отдельное окно на Windows):
$login = Read-Host 'Логин из whoami в Ubuntu' # Запомнить имя пользователя VM.
ssh -p 2222 "$login@127.0.0.1" # Подключиться через NAT; yes только при совпадении ED25519 fingerprint.
При первом входе сравни SHA256 с консолью VM, затем введи пароль Ubuntu.
Если REMOTE HOST IDENTIFICATION HAS CHANGED после переустановки VM:
сначала заново посмотри fingerprint командой выше В КОНСОЛИ VirtualBox.
Только для своей переустановленной VM в Windows PowerShell:
ssh-keygen -R '[127.0.0.1]:2222' # Удалить устаревший ключ только этого адреса и порта.
ssh -p 2222 "$login@127.0.0.1" # Сверить новый ED25519 SHA256 с VM; yes только при совпадении.
Несовпадение — не подтверждай; другие ошибки подключения → HELP §12.

3. ПРОЕКТ И ПУБЛИКАЦИЯ — Ubuntu Bash (после SSH-входа либо в консоли VM)
Если API уже установлен, сначала обновление по HELP §8, без переустановки ОС.
mkdir -p "$HOME/app" # Создать папку исходников своего пользователя.
git clone https://github.com/xtwze/examLinux.git "$HOME/app/examLinux" # Скачать проект; папка уже есть → HELP §9.
cd "$HOME/app/examLinux" # Перейти к ExamApi.csproj и шаблонам конфигурации; ошибка → HELP §9.
test "$(id -u)" -ne 0 # Убедиться, что работаешь обычным пользователем; при ошибке выйди из root.
sudo install -d -m 755 -o "$(id -un)" -g "$(id -gn)" /var/www/app # Один раз создать каталог 755 с собой как владельцем.
dotnet publish ExamApi.csproj -c Release -o /var/www/app # Собрать прямо в каталог задания без sudo; ошибка → HELP §1 или §5.
Путь /var/www/app и режим каталога 755 прямо требуются заданием.

4. SYSTEMD — Ubuntu Bash (тот же обычный пользователь)
sed "s/^User=YOUR_USER$/User=$(id -un)/" examapi.service | sudo tee /etc/systemd/system/examapi.service > /dev/null # Подставить свой логин и установить службу.
cat /etc/systemd/system/examapi.service # Проверить User=свой_логин, пути /var/www/app и /usr/bin/dotnet; не root/YOUR_USER.
sudo systemctl daemon-reload # Перечитать установленный unit.
sudo systemctl enable examapi # Включить запуск API при загрузке.
sudo systemctl restart examapi # Запустить API с установленным unit, в том числе при повторной настройке.
systemctl status examapi --no-pager # Проверить active (running); ошибка → HELP §2.
curl -fS http://127.0.0.1:5000/api/health # Проверить API напрямую: JSON Healthy; при старте повторить через пару секунд.
ps -o user,pid,args -p "$(systemctl show -p MainPID --value examapi)" # Проверить, что процесс работает от своего логина.

5. NGINX — Ubuntu Bash (отдельная учебная VM с одним сайтом)
sudo cp examapi.nginx.conf /etc/nginx/sites-available/examapi # Установить HTTP-прокси с порта 80 на 127.0.0.1:5000.
sudo ln -sfn /etc/nginx/sites-available/examapi /etc/nginx/sites-enabled/examapi # Включить сайт ссылкой.
sudo rm -f /etc/nginx/sites-enabled/default # Отключить стандартный сайт этой учебной VM.
sudo nginx -t # Проверить синтаксис; продолжать только при successful, иначе HELP §3.
sudo systemctl enable --now nginx # Включить службу и автозапуск.
sudo systemctl reload nginx # Применить проверенный конфиг.
curl -fS http://127.0.0.1/api/health # Проверить прокси: JSON Healthy.
curl -fS http://127.0.0.1/api/products # Проверить список товаров через Nginx.
curl -fS http://127.0.0.1/api/categories # Проверить список категорий через Nginx.

6. WINDOWS — новое окно PowerShell на Windows, не внутри SSH
$base = 'http://127.0.0.1:8080' # Адрес хоста: NAT переводит 8080 в порт 80 VM.
Invoke-RestMethod "$base/api/health" # Проверить всю цепочку: ожидается Healthy.
Invoke-RestMethod "$base/api/products" # Получить товары.
Invoke-RestMethod "$base/api/categories" # Получить категории.
Те же три URL можно открыть в браузере Windows. Не забудь :8080.
Ожидается JSON; / и /swagger в Production дают 404. Сбой только Windows → HELP §7.

7. ФИНИШ — Ubuntu Bash
systemctl is-enabled examapi nginx ssh # Ожидается enabled для трёх служб.
systemctl is-active examapi nginx ssh # Ожидается active для трёх служб.
history # Показать команды, выполненные в этом интерактивном Bash.
history -a # Сохранить команды этого сеанса в историю пользователя.
history > "$HOME/exam-history.txt" # Сохранить копию для показа комиссии.
На тренировке после перезагрузки повтори SSH и три запроса из Windows.
Для защиты: systemd держит API от моего пользователя; он же владеет публикацией;
Nginx :80 → API 127.0.0.1:5000; NAT Windows :8080 → VM :80. Данные в памяти.
