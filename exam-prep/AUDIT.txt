ВЕРДИКТ

Код приложения подходит для задания. Недостающих моделей, контроллеров,
Health Check и конфигов нет. Основные проблемы — в инструкции развёртывания
и подготовке сети. Полностью сдаваемое состояние требует выполнения
команд в настоящей VM и демонстрации с Windows.
Этот аудит описывает исходный commit fe1426f до исправлений.
По результатам аудита README исправлен, комплект добавлен в exam-prep/,
добавлен .gitignore, а bin/ и obj/ удалены из индекса Git.
Перечисленные ниже ошибки старого README относятся к исходной версии.
Код API и конфиги не менялись; границы проверки остаются прежними.

СОПОСТАВЛЕНИЕ ВСЕХ ТРЕБОВАНИЙ

1. Простой API без подключения к БД — выполнено в коде.
   ProductsController.cs и CategoriesController.cs содержат статические
   List<Product>/List<Category>. Подключения к БД и ORM нет.
   После перезапуска данные сбрасываются — это соответствует работе в памяти.

2. Две сущности модели — выполнено.
   Models/Product.cs: Id, Name, Price, Stock.
   Models/Category.cs: Id, Title, Description.

3. Два контроллера для моделей — выполнено.
   Controllers/ProductsController.cs и Controllers/CategoriesController.cs.
   Оба имеют GET списка/одной записи, POST, PUT и DELETE.
   CRUD реально проверен на Linux, включая 404 после удаления.

4. Один контроллер Health Check — выполнено.
   Controllers/HealthController.cs, GET /api/health → 200,
   JSON с status=Healthy, timestamp, version.
   Это простая проверка ответа процесса; глубокой диагностики зависимостей
   задание не требует. Добавлять отдельный health-фреймворк не нужно.

5. Заранее подготовить приложение и разместить в GitHub — выполнено.
   Указанный публичный репозиторий успешно клонирован; commit указан выше.

6. Установить .NET на VM, желательно 6 — необходимо выполнить в VM.
   ExamApi.csproj нацелен на net6.0. Нужен SDK для сборки;
   один runtime недостаточен. Основной сценарий использует пакеты Ubuntu
   22.04: git, curl, nginx, dotnet-sdk-6.0.
   .NET 6 можно оставить для соответствия пожеланию задания.
   Поддержка версии закончилась 12.11.2024; для нового публичного сервиса
   выбрали бы поддерживаемую версию. Миграция не нужна для этого зачёта.

7. Клон в /home/{пользователь}/app — предусмотрено, требуется выполнить.
   mkdir -p "$HOME/app"; cd "$HOME/app"; git clone URL .
   $HOME соответствует /home/{пользователь} у обычного пользователя Ubuntu.
   В старом README адрес репозитория является незаменённым шаблоном.
   В комплекте исправлен на https://github.com/xtwze/examLinux.git.

8. Release в /var/www/app с правами 755 — исходная инструкция ошибочна.
   sudo mkdir + chmod 755 оставляет папку root:root; обычный пользователь
   не сможет выполнить dotnet publish -o /var/www/app.
   Исправленный порядок: publish в домашнюю папку → sudo cp в /var/www/app.
   Папка 755, root:root; www-data может читать результаты публикации.
   Исправленный порядок реально проверен в Linux-контейнере.

9. Демон systemd, запускающий DLL — конфиг есть.
   examapi.service: /usr/bin/dotnet /var/www/app/ExamApi.dll,
   WorkingDirectory=/var/www/app, User=www-data, Restart=always,
   ASPNETCORE_ENVIRONMENT=Production, WantedBy=multi-user.target.
   systemd-analyze verify прошёл. Дальше нужны daemon-reload,
   enable --now и проверка после перезагрузки именно в VM.

10. HTTP на порту 5000 — выполнено в конфигурации и проверено.
    appsettings.json: Urls=http://0.0.0.0:5000.
    Runtime сообщил именно этот адрес, запросы на 5000 успешны.
    В unit нет ASPNETCORE_URLS, но это не недостающая часть:
    приложение уже читает Urls из appsettings.json.

11. Nginx reverse proxy с 80 на 5000 — конфиг есть и проверен.
    examapi.nginx.conf: listen 80; proxy_pass http://127.0.0.1:5000.
    nginx -t прошёл; реальные CRUD-запросы через 80 успешны.
    Нужны установка пакета, включение сайта и отключение стандартного
    сайта в отдельной учебной VM — команды включены в 00-START.txt.

12. Показать API-запросы с Windows — частично описано в старом README.
    Не хватало настройки сети VirtualBox и примера для стандартного NAT.
    Добавлено правило Windows 127.0.0.1:8080 → VM:80 и WINDOWS.ps1.
    В скрипте используются ID, полученные в ответах API, вместо id=4.
    Windows и VirtualBox в этой проверке не запускались: это финальный
    шаг репетиции пользователя.

13. Вывести историю команд — предусмотрено, требует ручной демонстрации.
    history нужно выполнить в том же интерактивном Bash, где вводились
    команды. Историю можно дополнительно сохранить в exam-history.txt.
    Запуск setup.sh не добавит каждую его команду в обычную history.
    Поэтому основной маршрут — короткие блоки команд для ручного ввода.

ИСПРАВЛЕНИЯ ПО РЕЗУЛЬТАТАМ АУДИТА

Обязательно для надёжной инструкции:
— Заменить шаблон GitHub URL реальным адресом.
— Исправить публикацию и права по пункту 8.
— Добавить установку git и curl для минимальной VM.
— Добавить NAT-проброс и проверку обоих портов внутри Linux.
— Убрать обещание Swagger при обычном dotnet run: без launchSettings.json
  или явной переменной среды применяется Production, где Swagger отключён.
  Для сдачи достаточно API-маршрутов.
— В демонстрации CRUD использовать ID ответа, а не константу 4.
— Сделать включение сайта повторяемым: ln -sfn и rm -f для default.

Полезная уборка, не блокирует сдачу:
— Добавить .gitignore с bin/, obj/, .vs/ и *.user.
— Убрать уже отслеживаемые bin/ и obj/ из индекса Git; одного .gitignore
  недостаточно. Сейчас в репозитории лежат старые Windows .exe и кэши.
— Кратко объяснить сброс данных после перезапуска.

Не требуется заданием:
— База данных, Docker в экзаменационной VM, HTTPS, авторизация, CI/CD.
— Доработка многопоточных List<T> и валидации цен. Для учебной
  последовательной демонстрации это не блокер; для реального сервиса
  эти места потребуют отдельной доработки.
— ИИ-агент. Практичный вариант подсказок описан в AI.txt.

ФАКТИЧЕСКАЯ ПРОВЕРКА

Среда: одноразовый Ubuntu 22.04 Linux ARM64-контейнер,
официальный mcr.microsoft.com/dotnet/sdk:6.0-jammy.
.NET SDK 6.0.428, runtime из этого образа. Docker применялся только
для аудита, он не входит в предлагаемый стек экзамена.
Чистая копия исходников без .git, bin, obj. Сборка выполнялась обычным
пользователем examstudent; API запускался пользователем www-data.

Успешно:
— восстановление NuGet и dotnet publish -c Release;
— копирование публикации и права 755 root:root на /var/www/app;
— systemd-analyze verify оригинального unit;
— nginx -t оригинального reverse-proxy-конфига;
— 34 HTTP-проверки: Health Check; обе коллекции; создание, чтение,
  обновление, повторное чтение, удаление и 404 для обеих моделей;
  ожидаемые 404 на / и /swagger в Production;
  весь набор повторён напрямую на 5000 и через Nginx на 80.

Границы проверки:
— systemd не был PID 1 в контейнере: реальный запуск/авторестарт/автозагрузка
  через systemctl и reboot не подтверждены.
— Не проверялась VirtualBox VM пользователя, её Windows-сеть и x86-64.
— Пакет dotnet-sdk-6.0 найден в jammy-updates для ARM64; для сборки
  использован готовый SDK-образ. Установка SDK через apt на целевой VM
  отдельно не прогонялась.
— PowerShell-файлы просмотрены, но в Windows PowerShell не запускались.
— Ollama/модель не устанавливались; их скорость и ответы не проверены.

См. VERIFICATION.txt для фактического лога. Первая неудачная попытка curl
в нём относится к ожиданию старта процесса; дальнейшие проверки прошли.
