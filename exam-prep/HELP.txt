HELP — ОТКРОЙ ТОЛЬКО НУЖНЫЙ НОМЕР ПРИ ОШИБКЕ
Команды с # выполняются в Ubuntu Bash, кроме явно отмеченного PowerShell.

1. Permission denied / cannot stat при копировании
Причина: нет sudo, неверный путь или сборка не завершилась.
Исправление: вернись к шагу 3 START; HOME пишется как "$HOME", не HOME.
Проверка:
ls -l "$HOME/exam-publish/ExamApi.dll" /var/www/app/ExamApi.dll # Проверить исходную и установленную DLL.

2. examapi failed / HTTP 502 / порт 5000 не отвечает
Причина: неверный User, путь, runtime или порт занят.
Проверка причины:
sudo journalctl -u examapi -n 30 --no-pager # Прочитать ошибку запуска API.
grep '^User=' /etc/systemd/system/examapi.service # Проверить свой логин вместо YOUR_USER (217/USER).
dotnet --list-runtimes # Нужен Microsoft.AspNetCore.App 8.0.x из SDK 8.
sudo ss -ltnp 'sport = :5000' # Найти процесс на порту; свой dotnet run останови Ctrl+C.
Исправление: повтори установку unit из START §4; при ошибке доступа — §1.
sudo systemctl daemon-reload # Прочитать исправленный unit.
sudo systemctl reset-failed examapi # Сбросить ограничение стартов после устранения причины.
sudo systemctl restart examapi # Запустить исправленную службу.
curl -fS http://127.0.0.1:5000/api/health # Проверить Healthy; при старте повторить через пару секунд.

3. 5000 отвечает, порт 80 нет / Welcome to nginx
Причина: ошибка конфига или включён стандартный сайт.
sudo nginx -t # Найти файл и строку ошибки.
sudo tail -n 20 /var/log/nginx/error.log # Прочитать ошибку прокси.
Исправление: повтори START §5, не перезагружай Nginx при неуспешном nginx -t.
curl -fS http://127.0.0.1/api/health # Проверить Healthy через порт 80.

4. Unable to locate package dotnet-sdk-8.0
Причина: не обновлены списки, недоступен репозиторий или выключен компонент Ubuntu.
cat /etc/os-release # Уточнить выпуск только при сбое: нужен 22.04/24.04.
sudo apt update # Проверить доступность источников; сначала исправить ошибки загрузки.
apt-cache policy dotnet-sdk-8.0 # Проверить наличие Candidate.
Если Candidate отсутствует, включи universe:
sudo apt install -y software-properties-common # Установить средство управления компонентами apt.
sudo add-apt-repository -y universe # Включить официальный компонент Ubuntu.
sudo apt update # Обновить списки после включения.
sudo apt install -y dotnet-sdk-8.0 # Установить SDK и ASP.NET Core runtime.
dotnet --version # Проверить 8.0.x.
Не смешивай источники Microsoft и Ubuntu наугад.
Документация: https://learn.microsoft.com/en-us/dotnet/core/install/linux-ubuntu-install

5. clone / publish: сеть, NuGet или сборка
Причина: VM без сети, недоступен NuGet либо команда запущена не из проекта.
ip route # Проверить маршрут по умолчанию.
getent hosts github.com api.nuget.org # Проверить DNS двух нужных серверов.
curl -I https://api.nuget.org/v3/index.json # Проверить HTTPS к NuGet.
Исправление: VirtualBox → NAT → «Кабель подключён»; не отключай TLS-проверку.
cd "$HOME/app/examLinux" # Вернуться в каталог проекта.
dotnet publish ExamApi.csproj -c Release -o "$HOME/exam-publish" # Повторить сборку после исправления.
Проверка: код завершения 0 и создана ExamApi.dll в exam-publish.

6. 404 на / или /swagger
Причина: корневого маршрута нет; Swagger выключен в Production. Исправление: правильный URL.
curl -fS http://127.0.0.1/api/health # Проверить реальный маршрут API: Healthy.

7. Ubuntu отвечает, Windows не отвечает
Причина: не сохранён NAT, VM выключена, порт занят или UFW блокирует 80.
Исправление: проверь оба OK из START §0 и адрес с :8080.
Windows PowerShell:
Test-NetConnection 127.0.0.1 -Port 8080 # Проверить доступность проброшенного HTTP-порта.
Ubuntu Bash:
sudo ufw status # Проверить, активен ли firewall.
Только если active:
sudo ufw allow 80/tcp # Разрешить вход к Nginx, не открывая внутренний 5000.
Windows PowerShell:
Invoke-RestMethod 'http://127.0.0.1:8080/api/health' # Проверить Healthy после исправления.

8. Нужно обновить уже установленный API
Причина: старые файлы публикации. Сначала успешно повтори publish из START §3.
sudo systemctl stop examapi # Остановить процесс перед заменой DLL.
Затем повтори копирование и права из START §3.
sudo systemctl restart examapi # Запустить новую публикацию; данные в памяти сбросятся.
curl -fS http://127.0.0.1/api/health # Проверить ответ после обновления.

9. destination path already exists
Причина: проект уже клонирован. Не клонируй внутрь него и не удаляй свои файлы.
cd "$HOME/app/examLinux" # Перейти в существующий checkout.
git remote -v # Проверить, что это xtwze/examLinux.
git status --short # Проверить свои изменения перед обновлением.
Только если checkout чистый:
git pull --ff-only # Получить актуальные файлы без перезаписи своей работы.
ls ExamApi.csproj examapi.service examapi.nginx.conf # Проверить три нужных файла; продолжить START §3 с publish.

10. Unknown command verb у systemctl
Причина: опечатка. Исправление:
sudo systemctl daemon-reload # Перечитать unit; daemon-reload пишется через дефис.
systemctl status examapi --no-pager # Проверить состояние; запуск — START §4.

11. chmod: убрать чтение владельцу / добавить запись группе / убрать чтение всем
Причина Permission denied: root владеет файлом, поэтому нужен sudo.
Тренируйся на отдельном файле, не на DLL работающего API:
sudo install -m 644 /dev/null /tmp/exam-rights.txt # Создать root-owned учебный файл с исходным режимом 644.
sudo chmod u-r /tmp/exam-rights.txt # Убрать чтение владельцу, остальные права сохранить: 244.
sudo chmod g+w /tmp/exam-rights.txt # Добавить запись группе: 264.
sudo chmod a-r /tmp/exam-rights.txt # Убрать чтение у всех: 220.
stat -c '%a %U:%G %n' /tmp/exam-rights.txt # Проверить итог 220 root:root.
u — владелец, g — группа, a — все; + добавить, - убрать, = задать точно.
Для собственного файла sudo не нужен. Каталогу нужен x для прохода внутрь.

12. SSH не запускается / Windows не подключается
Причина: ключи, /run/sshd, ошибочный конфиг, NAT или firewall.
sudo /usr/sbin/sshd -t # Получить точную ошибку; нет вывода — синтаксис исправен.
sudo journalctl -u ssh -n 30 --no-pager # Прочитать причину failed.
Исправление host keys, /run/sshd, reset-failed и смены ключа Windows —
ПОЛНОСТЬЮ в START §2. Не удаляй существующие ключи сервера.
sudo ss -ltnp 'sport = :22' # Проверить слушатель после запуска ssh.
sudo ufw status # Проверить firewall; если active, выполни следующую команду.
sudo ufw allow 22/tcp # Разрешить SSH в активном firewall.
Windows PowerShell:
Test-NetConnection 127.0.0.1 -Port 2222 # Проверить NAT 2222 → 22; ожидается TcpTestSucceeded True.
Если ssh не найден: Параметры Windows → Дополнительные компоненты → OpenSSH Client.
Permission denied при входе: используй логин whoami и пароль Ubuntu, не Windows.
Проверка: SSH-вход по START §2. При несовпадении fingerprint не вводи yes.
Документация: https://man.openbsd.org/ssh-keygen
